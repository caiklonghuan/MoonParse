# Third-party materials and provenance

This inventory is the M0 source-of-truth for material that enters the repository, a Pack, a demo, or a release bundle. An item without a compatible license and a recorded origin is rejected from production artifacts.

## Repository source and fixtures

| Material | Location | Origin / usage | Release policy |
| --- | --- | --- | --- |
| MoonBit, JSON, Python and C corpus snippets | `languages/*/corpus/`, `grammars/corpus/` | Repository-authored minimal syntax fixtures; they are not imported upstream test suites. Language specifications are semantic references only, not copied source. | MoonBit corpus may become production evidence after the corpus manifest is frozen. Python and C fixtures remain experimental unless separately licensed and promoted. |
| Grammar DSL and parser-table fixtures | `grammars/`, `languages/`, `api/fixtures/` | Repository-authored inputs and generated compatibility fixtures. | Generated outputs are rebuilt from declared source; no opaque generated table is a source of truth. |
| MoonBit toolchain and core packages | MoonBit installation / registry cache | Toolchain dependency, not vendored source in this repository. | Version is locked by `toolchain.lock`; release provenance records the exact toolchain. |

## Development-only dependencies

| Material | Location | Role | Policy |
| --- | --- | --- | --- |
| `web-tree-sitter`, `tree-sitter-json` | `website/package-lock.json` | Existing Website comparison workbench only. | MIT-licensed npm dependencies according to the lockfile; not part of the champion runtime or A03 release payload. |
| Tree-sitter grammar input | user-provided importer input | Optional migration input for the future one-way importer. | The input Pack must carry its upstream URL and license. Importing never transfers an unrecorded grammar into a production Pack. |

## Removed generated binaries

M0-C04 removed the tracked legacy files `wasm/moonparse.wasm`, `website/public/moonparse.wasm`, `website/public/tree-sitter/tree-sitter.wasm` and `website/public/tree-sitter/tree-sitter-json.wasm`. They were build/development outputs, not source material; their pre-removal SHA-256 values are retained in the M0-C04 commit review. Future release bytes must be produced by the canonical assembly path and recorded in release provenance rather than committed to source control.

## Enforcement

1. `evidence/manifests/source-provenance.v1.json` enumerates the allowed source classes and release disposition.
2. A future production Pack must include its own `license` and source manifest; unknown scanner, grammar, corpus or generated bytes fail provenance validation.
3. `node_modules/`, `_build/`, `out/`, `dist/`, release binaries and caches are ignored and must not be committed as source artifacts.
4. Any new vendored source, copied corpus, generated grammar, demo media or external scanner requires a new row here plus an immutable source hash before it can enter a release candidate.
